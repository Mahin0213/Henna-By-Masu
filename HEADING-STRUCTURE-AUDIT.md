## 2. Problems

Checked against every item you listed. Most came back clean — stated plainly so you know what not to spend effort on.

| Check | Result |
|---|---|
| H1 count | **1** — correct |
| Duplicate headings | **None** |
| Empty headings | **None** |
| Headings inside images | **None** — all 15 images carry alt text, no text-in-heading-image |
| Heading nesting | **No skipped levels** — H1 → H2 → H3 throughout |
| Headings used only for styling | **None** — no heading tag is used for non-heading text |

Four real problems:

**P1 — Every heading is generated by JavaScript. Severity: Critical.**
The HTML response body is `<div id="app"></div>` plus script tags. All 22 headings are created at runtime by `app.jsx` and `sections.jsx`, compiled in-browser by Babel. Until the page is pre-rendered, Google's initial crawl sees **zero headings**. Every recommendation below is inert until this is fixed — it is the same finding as the crawlability audit, repeated here because it determines whether any of this reaches Google.

**P2 — The intro section has no heading, and its text is styled as one. Severity: Medium.**
`sections.jsx`, `Intro()`:

```jsx
<p style={{ fontFamily: "var(--font-display)", fontSize: "clamp(2rem,3.6vw,3.25rem)", … }}>
  Every line is personal. Every design is drawn for the moment it becomes part of your story.
</p>
```

This renders at **33px in Bodoni Moda** — visually the second-largest text on the page, larger than the FAQ H3s at 18px — inside a `<p>`. It is the one place where the visual hierarchy and the semantic hierarchy disagree. The section is also the only one on the page with no heading at all, so a screen reader's heading list skips silently from the H1 to "Four ways to wear henna".

**P3 — Three H2s carry no service or place signal. Severity: Medium.**

- `Selected work` — the portfolio of a Leicester henna artist, labelled with two words that could belong to any trade
- `Masuma` — a first name alone; no indication she is the artist
- `A design as individual as your celebration.` — the bridal section's H2, which never says "bridal"

These read beautifully and they are on-brand. The issue is that H2s are section-level topic signals, and three of the eight signal nothing about what the business does.

**P4 — Primary search intent is only partly represented. Severity: Medium.**

What is well covered: `Henna artist in Leicester` (H1), `Bridal mehndi`, `Eid mehndi` (H3s), `Henna and mehndi in Leicester` (FAQ H2), and six question H3s matching real long-tail queries.

What is missing from the heading layer entirely: **prices** (the £10/£30/£50 tiers appear in body copy and on `pricing.html`, but no heading on the homepage mentions them, and "how much is henna Leicester" is a high-intent query you already answer); and **bridal** as an H2 word, despite bridal being the highest-value service and having its own dedicated section.

One heading is also weaker than it looks: `Private celebrations` (H3) contains neither "henna" nor "mehndi", so as a standalone topic signal it says nothing.

## 4. Exact replacement copy

**Change 1 — Intro section: promote the styled line to an H2**

`sections.jsx`, `Intro()`:

```jsx
{/* Before — 33px display text inside a <p>, section has no heading */}
<p style={{ fontFamily: "var(--font-display)", fontSize: "clamp(2rem,3.6vw,3.25rem)",
  lineHeight: 1.24, letterSpacing: ".01em", color: "var(--ivory-50)", margin: 0, maxWidth: "18ch" }}>
  Every line is personal. Every design is drawn for the moment it becomes part of your story.
</p>

{/* After — same typography, now semantic. Identical rendering. */}
<h2 style={{ fontFamily: "var(--font-display)", fontSize: "clamp(2rem,3.6vw,3.25rem)",
  lineHeight: 1.24, letterSpacing: ".01em", color: "var(--ivory-50)", margin: 0,
  maxWidth: "18ch", fontWeight: 400, textTransform: "none" }}>
  Every line is personal
</h2>
<p style={{ font: "var(--type-body-lg)", color: "var(--text-body)", maxWidth: "44ch", margin: 0 }}>
  Every design is drawn for the moment it becomes part of your story.
</p>
```

Note `fontWeight: 400` and `textTransform: "none"` — without them the browser's `h2` defaults and the design system's uppercase heading rule would change the look. With them the visual output is unchanged.

**Change 2 — Services: one H3 word**

**Change 6 — New price section between Artist and FAQ**

This is the one structural addition. It is justified by content you already have — the three tiers on `pricing.html` — and by the FAQ question "How much is henna in Leicester?" that already sits on this page. It is not a heading created for SEO; it is a real section that was missing.

```jsx
function Prices() {
  const TIERS = [
    { h: "Simple henna — from £10", p: "Single-hand designs for a party or an evening out, drawn in a short sitting." },
    { h: "Semi bridal — from £30", p: "Fuller hands for the mehndi guest of honour, the sister, the mother of the bride." },
    { h: "Bridal mehndi — from £50", p: "Hands, feet and forearms across an unhurried session, with your own motifs worked in." },
  ];
  return (
    <section id="prices" style={{ padding: `${SECTION_Y} ${GUTTER}`, background: "var(--surface-page)",
      borderTop: "1px solid var(--border-hairline)" }}>
      <div style={{ maxWidth: "var(--content-max)", margin: "0 auto" }}>
        <Reveal>
          <SectionHeading eyebrow="Prices" title="Henna and mehndi prices in Leicester"
            lede="Starting prices. The final quote depends on the design and coverage, and is confirmed before your date." />
        </Reveal>
        <div className="grid-3" style={{ marginTop: "56px" }}>
          {TIERS.map((t, i) => (
            <Reveal key={t.h} delay={i * 110} style={{ borderTop: "1px solid var(--border-hairline)",
              paddingTop: "24px", display: "flex", flexDirection: "column", gap: "12px" }}>
              <h3 style={{ fontFamily: "var(--font-display)", fontWeight: 400,
                fontSize: "clamp(1.125rem,1.8vw,1.375rem)", lineHeight: 1.2, letterSpacing: ".03em",
                textTransform: "uppercase", color: "var(--ivory-50)", margin: 0 }}>{t.h}</h3>
              <p style={{ font: "var(--type-body)", color: "var(--text-body)", maxWidth: "40ch", margin: 0 }}>{t.p}</p>
            </Reveal>
          ))}
        </div>
        <div className="cta-row" style={{ marginTop: "48px" }}>
          <Button variant="outline" size="lg" href="pricing.html">Full price list</Button>
        </div>
      </div>
    </section>
  );
}
```

It reuses `SectionHeading`, `Reveal`, `Button`, `.grid-3` and the existing hairline-and-uppercase card pattern from the FAQ — no new visual vocabulary.

## 5. Implementation instructions

**Files to edit:** `sections.jsx` (changes 1–6), `app.jsx` (register the new section).

1. Apply changes 1–5 in `sections.jsx` exactly as written above.
2. Add the `Prices` component to `sections.jsx`, then add `Prices` to the export line:
   ```js
   Object.assign(window, { Reveal, Intro, Services, Gallery, BridalFeature, Process, Artist, Prices, Faq, Testimonial, Booking, Footer, GUTTER, SECTION_Y, LINEN });
   ```
3. In `app.jsx`, add `Prices` to the destructure and place it between `<Artist />` and `<Faq />`:
   ```jsx
   const { …, Artist, Prices, Faq, … } = window;
   …
   <Artist />
   <Prices />
   <Faq />
   ```
4. Optionally add `["Prices", "#prices"]` to the `NAV` array.
5. Rebuild `site/` (filename rewrite) and re-upload.

**Two cautions.**

Both new headings need `fontWeight: 400` and — where the text is sentence case — `textTransform: "none"`, or the design system's heading rules will change their appearance. The snippets above include this.

And the load-bearing point: **none of these headings are visible to Google until the page is pre-rendered.** Today the HTML response contains no headings at all, so this audit describes a structure that only exists after JavaScript runs. Fix the pre-rendering first; these changes then compound with it.

---

## Summary

The existing structure is mechanically sound — one H1, correct nesting, no duplicates, no empties, no styling abuse. Better than most sites audit at this stage.

The gaps are editorial, not technical: one section styled like a heading without being one, three H2s that describe mood rather than service, and no price heading despite prices being a question the page already answers. The six changes above address all of it while leaving eight of the existing headings untouched.
